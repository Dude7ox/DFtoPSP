## Classic-parity completion of character creation

- Province map: the race step walks a cursor over `TMAP00I0.IMG` and decodes
  the chosen race from the index-only `TAMRIEL2.IMG` pixel under it (pixel
  value = race id), then shows the classic description dialog and plays the
  spoken province id (DAGGER.SND 209-216).
- Class questions: ten of the forty `TEXT.RSC` 9000 subrecords, the classic
  FALL.EXE answer table and the `CLASSES.DAT` weight lookup produce the
  recommended class, offered in the accept / choose-manually dialog; every
  answer plays `SoundClips.Ignite`.
- Special advantages and disadvantages: the full `difficultyDict` cost tables
  (magery x1..x3, immunity, regeneration variants, forbidden materials per
  material, phobias, critical weakness, ...), max seven picks, difficulty
  total clamped to -12..40; picks mutate the career exactly where
  `CLASS??.CFG` stores them and round-trip through the save file.
- Summary screen revisits face and reflexes (critical chance
  `50-10*(reflex-2)` %) before the character is accepted.
- Save format v5 adds reflexes, magery option and the pick list; v1-v4 still
  load. `TEXT.RSC` gained `subLines()` for numbered subrecords (9000).
- New data files (5): `TMAP00I0.IMG` companion `SCRL00I0.GFX`/`SCRL01I0.GFX`
  scroll art, `CHAR05I1.IMG` summary highlight and the `ROGUE.CEL`,
  `MAGE.CEL`, `WARRIOR.CEL` constellation animations; manifest now 618 files.

- Monsters: editor spawn markers (archive 199 records 15/16) are parsed from every
  resident block; random markers resolve through the classic encounter tables
  (seeded with the dungeon `LocationId`), fixed markers carry their mobile type.
- Career records (`ENEMY###.CFG`) are read from the original `MONSTER.BSA` at run
  time; combat numbers come from the generated MIT-licensed DFU tables
  (`src/core/EnemyData.cpp`, regenerated by `tools/gen_enemy_data.py`).
- AI: sight through the static wall set plus closed doors, aggro/lose ranges,
  wander, melee attack sequences with the original per-frame damage frame,
  hurt state, corpses that persist for the session.
- Player combat: melee swing with hit chance and armour mitigation, HP, death
  respawn at the dungeon entrance; kills award XP/gold and level-ups raise
  max HP, skill and lockpick; locked doors can be picked.
- Binary save/load (`DFPS` magic, format v2) covering player, progression,
  monsters, spawn/death keys; v1 saves still load.
- Original `FONT000?.FNT` bitmap faces parse with a DFU-compatible reader
  (header, 240-entry metric table, 16-bit row bitfields); FONT0001 (14 px gothic)
  and FONT0003 (5x7) verified, and `drawText` blits with a 1 px drop shadow.
- `tests/test_core` covers RLE texture parity, billboard scale, marker parse,
  wall line-of-sight, encounter rolls, simulation stability, a line-of-sight-verified
  melee kill with XP/gold award, lockpick success rates, FNT metrics/bitfields/blits,
  and the save/load round trip (format v2; v1 saves remain readable).

- Audio (see `docs/AUDIO.md`): `MIDI.BSA` (131 HMI songs) parses track-by-track -
  PPQN 480, 120 ticks/s, 104,827 notes across the corpus, every track reaching its
  end-of-track meta; `DAGGER.SND` (459 records) yields the classic 8-bit unsigned
  mono 11025 Hz samples, addressed by record index (`SfxId` mirrors DFU's
  `SoundClips` enum; per-monster move/bark/attack triples are baked into
  `src/core/EnemyData.cpp`).
- Synthesizer: 28 voices (22 music + 6 samples) at 22050 Hz stereo. A synthetic A4
  measures 440 Hz dominant with both neighbouring semitones more than 5x lower,
  `D1.HMI` at t~24 s measures 65.41 Hz for its written C2, two independent synths
  render bit-identical PCM, and 60 s renders peak at 15450-26113 with no clipping.
- Mix cost on this host (Xeon 2.60 GHz, `-O2`): 60 s of `D1.HMI` mixed in 0.172 s
  wall (348x realtime), the dense `TAVERN.HMI` in 0.231 s (260x realtime).
- Gameplay cues are spatialised: volume `110 - 70*d/2200` clamped to `[25,110]`,
  pan +-90 deg from the camera right vector. Which swing/impact sample plays is
  rolled on a separate cosmetic RNG, so classic combat rolls stay byte-identical
  with earlier builds.
- `docs/audio.wav`: 16 s of `DUNGEON.HMI` with a swing, impact, rat bark, footsteps,
  a door, a player hit and a body fall staged on a timeline by the host renderer
  (peak 17923, rms 2933).

## PSP implementation

- GU/GE hardware renderer with T8 indexed textures and a shared 256-entry CLUT8888.
- Fixed 48-slot 128×128 texture cache (~768 KB VRAM) plus double 512×272 5650 framebuffers
  and a 4444 depth buffer (~835 KB), fitting the PSP's 2 MB EDRAM budget.
- CPU texture uploads use `sceGeEdramGetAddr()`; GE commands use VRAM offsets.
- 3×3 resident dungeon blocks, streamed as the player crosses 2048-unit block boundaries.
- Door states are remembered per block instance while streaming.
- HUD text is drawn through GE from a font atlas baked into EDRAM: one 256x512 T8
  texture holding FONT0001 (status/door hints) and FONT0003 (help line) plus a
  dedicated CLUT, ~128 KB inside the 2 MB budget, with the classic drop shadow;
  `pspDebugScreen` remains only as fallback and for fatal/diagnostic screens.
  The host renderer blits the same faces into its framebuffer.
- Exit callback thread, analog/DPad controls, noclip, gravity/floor snap, fall recovery.
- Monster billboards animate per frame (T8 slots keyed by archive/record/frame),
  mirrored for the eastern orientations, with a depth-tested health bar.
- Square swings the weapon; X opens doors and picks locked ones (chance scales with
  the lockpick skill and level; failure aggros monsters near the door).
- Kills award XP and gold; level-ups raise max HP (full heal), skill and lockpick.
  HUD shows level and gold; save format v3 stores progression including the kill
  counter (v1 and v2 saves still load).
- Select cycles UI windows: off, HELP, CHARACTER and MESSAGE LOG. Panels are
  translucent plates with a FONT0001 title and FONT0003 body lines (core `Ui`
  builds the content for both platforms; GE draws them via `queueRect` plus the
  text queue, the host blits the same layout, `--ui char|help|log`, docs/ui.png).
- The message log is a 32-line ring fed by hits, misses, kills, level-ups,
  lockpick results and monster damage; the CHARACTER sheet shows level, XP,
  HP, armor, weapon skill, lockpicking, gold, kills and the dungeon name.
- Travel: `listRegionDungeons()` joins MAPNAMES/MAPPITEM/MAPDITEM into the classic
  per-region dungeon list (571 enterable locations in region 16); the TRAVEL window
  scrolls it with the DPad and X enters the selected dungeon (career persists,
  per-dungeon state resets). Boot restores the saved region/exteriorId location.
  World simulation pauses while any window is open. `docs/travel.png`.
- Location names: `loadDungeonLayout()` now resolves the full 32-character MAPNAMES
  name; the in-record name is only a truncated tail of it.
- Block-name fix: the RDB letter table followed DFU's `N,W,L,S,B,M` order, not the
  previously used `B,N,W,M,S`; with the wrong order most dungeons decoded to
  non-existent blocks (and the test dungeon silently loaded substitute blocks).
  All sampled region-16 locations now enter, including cemeteries.
- Frustum culling (core `Cull`): six-plane test per wall triangle and a sphere
  test for flats/doors billboards, shared by the GE and software renderers.
  At the starting area 9076 of 14950 triangles are rejected before vertex
  submission (61%) and the rendered frame stays pixel-identical; host `--stats`
  prints submitted/culled counts. PSP HUD now shows the measured fps.
- Automap window (Select cycle, sixth state): `buildAutomap()` projects the
  horizontal edges of vertical wall triangles of every resident block plus the
  door outlines and a player arrow into a north-up panel (core `Automap`,
  host `--ui map`, PSP GE `GU_LINES` via `queueMap`), `docs/automap.png`.
- Combat accuracy fix: `enemySwingHits`/`playerSwingHits` compared
  `DfRandom::percent()` (1..100) against a 0..1 fraction, so monsters could
  never land a blow; both now scale to percent and player swings roll to hit
  (0 damage = miss, logged as such).
- Audio output on device: a dedicated thread (priority `0x12`, 32 KB stack,
  USER|VFPU) renders 512-frame blocks into a 64-byte-aligned double buffer and
  feeds `sceAudioSRCChReserve`/`sceAudioSRCOutputBlocking` at 22050 Hz, so the
  hardware sample-rate converter does the upsampling; firmware without SRC falls
  back to `sceAudioChReserve` at 44100 Hz. The game thread only pushes cues into a
  64-slot lock-free ring and never blocks on audio. All six audio imports
  (`sceAudioSRCChReserve/OutputBlocking/ChRelease`, `sceAudioChReserve/Release`,
  `sceAudioOutputBlocking`) resolve against `libpspaudio.a`.
- Music and effects in play: dungeon theme `D{1 + exteriorId % 10}.HMI` (fallback
  `DUNGEON.HMI`), swing/impact/kill/level-up, monster move/bark/attack, player hurt,
  body fall, spatialised doors, lockpick grind, alternating footsteps, ~25 s ambience
  (drips/wind) and a death sound; travelling restarts the theme for the new location.
- Start writes `SAVE0.DFS` next to the data folder and the game restores it on boot.
- Boot mounts every existing data candidate as a VFS root (`data/`, `data/ARENA2/`,
  `ms0:`/`ef0:`/`host0:` game-directory variants, nested `ARENA2/`, relative fallbacks);
  mod lists are loaded from the game base, the save directory and the working directory.
- A fatal missing-file error prints an on-device diagnostics panel: `sceIoGetcwd`,
  a directory probe per candidate root, an `fopen` probe per mounted root and a
  stdio write/read self-test in the save directory.

## Not validated

- Real PSP execution beyond the boot screen: an earlier EBOOT was confirmed to run on
  PPSSPP and a PSP-3000 up to the missing-data fatal (user report); later builds changed
  data-root discovery, added the diagnostics panel, UI windows, travel and audio, but have
  not been run on a device here.
- Audio on hardware: SRC channel availability/behaviour, audio-thread priority against the
  GU renderer, and audible output are unverified; only host-side rendering is measured.
- Frame rate on hardware with the audio thread running.
- Long-play stability and memory fragmentation.
- Full collision robustness across all blocks.
- GU texture-coordinate convention on real hardware/emulator (implemented from SDK samples,
  but not visually confirmed here).

## Known gaps

- No inventory, quests, dialogue or spells yet; the UI windows
  (help/character/log/travel/automap) render in the original faces, and
  inventory/quest screens can reuse the same panel code. Inventory is blocked by
  the missing `ITEMS.BSA` in the cached data source.
- Music covers dungeons only: the archive also holds weather and town themes that
  can be routed once overworld data exists, and the densest theme
  (`TAVERN.HMI`) steals 8 notes per minute at the 22-voice music budget.
- Overworld travel is blocked by missing terrain data (`WOODS.WLD` is not part of the
  shipped freeware subset).
- Only the test dungeon layout is wired into the PSP startup path.
- Data provenance limitations remain; see `DATA.md`.
- The manually bootstrapped PSPSDK link emits `psp-fixup-imports` ordering warnings in this
  sandbox; the EBOOT packs successfully, but this is one more reason hardware validation is
  still required.
